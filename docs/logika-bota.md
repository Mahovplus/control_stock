# Логика бота учёта остатков. Версия 1.0 (утверждена)

Дата: 12.10.2026. Статус: **утверждена Даниилом 12.10.2026**. Код пишем строго по этой версии; любые изменения логики сначала вносятся сюда.

Пометки:
- **[решено]** Даниил сказал прямо.
- **[по умолчанию]** выбрал я, можно поменять.
- **[проверить]** зависит от iiko, не подтверждено на вашем ключе.

## 1. Зачем бот

Су-шеф всегда знает, сколько порций каждого порционного блюда осталось. Бот сам предупреждает, когда блюдо заканчивается, ставит его в стоп, сообщает официантам, когда оно вернётся, и не теряет порции, от которых гость отказался.

## 2. Кто участвует

| Роль | Что делает | |
|---|---|---|
| Су-шеф | Получает уведомления, пополняет остатки, делает утренний пересчёт, решает судьбу отменённых порций | [решено] |
| Чат официантов | Только читает: стоп, когда будет готово, снова в продаже | [решено] |
| Повара | В первой версии бота не пользуются | [решено] |

## 3. Четыре «кармана» для каждой порции

Бот хранит каждое блюдо в четырёх числах:

1. **Свободно**: можно продать. Это и есть «остаток».
2. **В работе**: пробито, ещё не оплачено (готовится, отдано, ждёт оплаты). Это «коридор для валидации».
3. **Продано**: заказ оплачен.
4. **Списано**: не продано, но использовано (с комментарием су-шефа).

Порция двигается только между этими карманами, поэтому всё сходится: что было = свободно + в работе + продано + списано.

## 4. Путь одной порции [решено]

```
Пробили и отправили на кухню
   → Свободно −1, В работе +1   (минус сразу, чтобы не продать лишнее)

Заказ оплачен (чек закрыт)
   → В работе −1, Продано +1

Гость отказался / позицию удалили из заказа после отправки на кухню
   → бот спрашивает су-шефа:
       [Вернуть в остаток]   → В работе −1, Свободно +1  (пойдёт на следующий заказ)
       [Списать]             → В работе −1, Списано +1, бот просит комментарий
```

Уточнения:
- Минус делается в момент **отправки на кухню** (печать бегунка). Позицию, удалённую до отправки, бот не считал, спрашивать не о чем. [по умолчанию]
- Стадии «готовится» и «отдано» бот показывает, только если iiko их присылает. В документации iikoCloud у позиции заказа есть статусы: добавлена, напечатана, готовится, готова, подана. [проверить] Обычно эти статусы заполняются, если на кухне стоит кухонный экран. Если кухня работает только с бумажными бегунками, будет одна стадия «в работе». Логика подсчёта от этого не меняется.
- При удалении позиции iiko передаёт тип удаления (со списанием или без) и комментарий официанта. [проверить] Бот покажет это су-шефу как подсказку, но решает всё равно су-шеф.
- **Отказ гостя:** вопрос су-шефу приходит **сразу**, как только позицию удалили. [решено]
- **Вечерняя сводка:** в конце смены бот присылает су-шефу **одним сообщением** всё, что он ещё не решил: отказы без ответа и позиции, оставшиеся «в работе» (не оплачены и не удалены). У каждой те же кнопки. [решено] Время конца смены задаётся в настройках. [по умолчанию]

## 5. Уведомления и стоп-лист

| Событие | Что делает бот | |
|---|---|---|
| Свободно стало 3 | Пишет су-шефу: «Осталось 3 порции: Вителло тоннато». Один раз, не после каждой продажи | [решено] порог 3 для всех |
| Свободно стало 0 | **Сразу** пишет в чат официантов «Вителло тоннато в стопе». Ставит в стоп в iiko (если доступ позволяет) или пишет су-шефу «Поставь в стоп вручную». Спрашивает су-шефа «Через сколько будет?» | [решено 14.10] официанты узнают первыми, не дожидаясь су-шефа |
| Пробили, а свободных порций нет | Срочно пишет **су-шефу и в чат официантов**: «Вителло тоннато пробили, а порций нет». Остаток в базе **не уходит ниже 0**. Решение принимает су-шеф | [решено] |

Повторное «осталось 3» придёт только после пополнения выше 3.

**Пробили сверх остатка, подробно.** [решено]
- Бот записывает такую позицию в журнал как «сверх остатка, ждёт решения», но в карманы её не кладёт. Свободно остаётся 0.
- Су-шеф решает сам и говорит официанту. Если проблему решили (например, сделали ещё порцию), су-шеф кнопкой «Пополнить» добавляет 1, и бот её учитывает.
- [по умолчанию] Добавленная так порция сначала закрывает ожидающую позицию «сверх остатка»: она уходит в «в работе», а дальше идёт обычный путь до оплаты. Свободно при этом остаётся 0, чтобы порцию не продали второй раз. Если такую позицию удалили из заказа, запись просто закрывается.
- [по умолчанию] Если позицию «сверх остатка» оплатили, а су-шеф её не пополнил, она попадает в вечернюю сводку как расхождение.

## 6. Возврат блюда в продажу [решено, уточнено 14.10]

Главное: официанты узнают о стопе как можно раньше, а су-шефа, который работает у плиты, бот дёргает минимально.

1. Свободно стало 0 → **сразу** в чат официантов: «Вителло тоннато в стопе. Когда вернётся, сообщу». Су-шефа бот для этого не ждёт.
2. Су-шефу одно сообщение с кнопками: **1 час / 2 часа / 3 часа** (одно нажатие).
3. Су-шеф нажал → в чат официантов **вторым сообщением**: «Вителло тоннато будет примерно через 2 часа».
4. По таймеру бот спрашивает су-шефа: «Вителло тоннато готово? [Да] [Нет]».
   - **Да** → «Сколько порций?» → Свободно + N → снять стоп в iiko (или команда вручную) → в чат официантов: «Вителло тоннато снова в продаже».
   - **Нет** → снова выбор времени, снова сообщение официантам.

Если су-шеф занят и не отвечает [по умолчанию]:
- Через **15 минут** бот **один раз** напоминает тот же вопрос с теми же кнопками. Больше не пишет, чтобы не отвлекать.
- Стоп от этого не снимается: официанты уже знают, что блюда нет.
- Если су-шеф раньше пополнил блюдо кнопкой «Пополнить», бот ничего не спрашивает: блюдо уже в продаже, официанты получают «снова в продаже».

## 7. Ручные действия су-шефа (кнопки)

| Кнопка | Что делает |
|---|---|
| Остатки | Список блюд: свободно / в работе |
| Пополнить | Выбрать блюдо → ввести количество. Если блюдо было в стопе, выходит из стопа |
| Утренний пересчёт | Бот по очереди спрашивает фактическое количество каждого блюда. Разницу с тем, что было в боте, записывает как «расхождение» |
| В работе | Что пробито и не оплачено |

## 7а. Расхождения: причина и месячный отчёт [ОТЛОЖЕНО 13.10, идея сохранена, в код не берём]

Идея Даниила: пересчёт нашёл меньше, чем в боте, значит порции куда-то ушли. Бот спрашивает причину и раз в месяц присылает сводку.

Пример: пополнили котлету на 5, утром насчитали 3. Расхождение −2.

1. **Сразу при пересчёте** бот спрашивает су-шефа: «Котлета: расхождение −2. Почему?» и показывает кнопки причин: [Сгорело] [Испортилось] [Потерялось] [Ошибка учёта] [Другое]. При «Другое» бот просит написать причину текстом. [решено: спрашивать сразу; набор кнопок по умолчанию]
2. Причина сохраняется в журнале рядом с расхождением: дата, блюдо, сколько, причина, кто.
3. Если су-шеф не ответил, расхождение остаётся «без причины» и попадает в вечернюю сводку вместе с другими нерешёнными вопросами (раздел 4). [по умолчанию]
4. Если порций **больше**, чем в боте (расхождение с плюсом), бот тоже спрашивает причину, но с другими кнопками: [Не пробили в кассе] [Ошибка учёта] [Другое]. [по умолчанию]
5. **Месячный отчёт:** 1-го числа каждого месяца в 10:00 бот присылает су-шефу все расхождения за прошлый месяц: по датам, по блюдам, с причинами и итогом по каждой причине. [решено: раз в месяц; дата и время по умолчанию]
   Пример строки: «15.06 · Котлета · −2 · Сгорело».
   Итог: «Сгорело: 5 порций, Испортилось: 3, Без причины: 1».
6. Кнопка «📊 Расхождения» в меню показывает тот же отчёт за текущий месяц в любой момент. [по умолчанию]

Совет как повару: кнопки быстрее текста. Утром на пересчёте у су-шефа руки заняты, а нажать «Сгорело» он успеет. Текст нужен только для «Другое».

## 8. Связь с iiko

- Бот получает заказы из iikoCloud API (события об изменении заказов или регулярный опрос). [проверить] видны ли заказы, созданные на кассе, без дополнительного шага.
- Бот следит только за блюдами из своего списка порционных позиций. Список связывается с меню iiko по коду блюда, не по названию.
- Стоп-лист: читать, ставить, снимать. Для изменения нужно право «Data: changing stoplists» и iiko версии 8.6.1 или новее. [проверить]
- Если связи с iiko нет больше 10 минут, бот пишет су-шефу: «Не вижу заказы из iiko, остатки могут быть неточными». [по умолчанию]

## 9. Хранение

Локальная база SQLite (один файл). [решено] В ней:
- блюда: код в iiko, название, свободно, в работе, в стопе или нет;
- журнал: каждое движение порции (кто, когда, откуда куда, комментарий), у расхождений ещё и причина;
- таймеры «когда будет готово» и напоминания су-шефу;
- настройки: порог (3), чат су-шефа, чат официантов, конец смены.
